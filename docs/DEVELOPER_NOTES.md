# MacLink 1.4.1 developer notes

Connector source/local build and published website installer: **1.4.1**. Native bundle versions read `app_runtime.VERSION`; do not relabel an older public DMG when changing source versions.

Update checks run only when requested. If GitHub has no stable public release, the Connector reads the fixed repository installer manifest and verifies its size and SHA-256 ETag against a HEAD request to the fixed website DMG URL. Unpublished source metadata cannot become an available update by itself. The check does not download or install the DMG, and a local version newer than the public installer displays the actual published version.

MacLink provides a macOS menu bar Connector and a Korean/English browser client. The public origin is `https://www.maclink.cloud`. The Connector opens outbound connections; it does not expose an inbound control listener.

## Authentication and credentials

Owners sign in with Google OpenID Connect, using state, nonce, PKCE and an opaque HttpOnly application session. Configure `GOOGLE_CLIENT_ID`, secret `GOOGLE_CLIENT_SECRET`, and `AUTH_BASE_URL=https://www.maclink.cloud` before activating this source. Preserve the existing secret `TURN_CONFIG_KEY`; never place credentials in source, logs or client bundles. See [Google setup](GOOGLE_LOGIN_SETUP.ko.md).

Google subject identifiers own devices. Equal email addresses never automatically merge accounts. A signed-in owner can explicitly import one legacy device with its existing connection-key JSON. The atomic claim checks the key and current ownership, ends that device's old sessions and keeps its Connector key. Other devices and TURN settings remain with the previous account. A device already owned by another Google account cannot be claimed.

Remote access requires a live Google login owning the registered device. GET devices/:id/ice and POST devices/:id/connect create approved same-account connections. Every session API additionally requires the initiating login cookie plus a session bearer. Logout, login rotation/expiry and ownership changes end access. Invitation routes and tables are removed.

## Connector registration

The normal enrollment path begins in the Connector: open the system browser, sign in with Google, check the Mac name, enter the Connector's six-digit code in the browser, and explicitly approve registration. The browser no longer creates a separate registration and downloads a JSON key as the default setup path. Existing valid local registration is reused across launches and app updates; names and email addresses are never used to merge devices automatically.

The Connector generates an enrollment request ID, a private polling proof and its own device credential. Only the credential hash reaches the server. The browser URL contains the public request ID, never a Connector secret. Browser approval requires a live Google session, an origin check and the confirmation code known to the requesting Connector. Pending browser metadata never discloses that code; failed attempts are bounded across accounts. Approval is atomic and pending requests expire after ten minutes. The approved metadata remains recoverable with the same private proof for up to 24 hours, so a lost reply does not create another device. Polling returns registration metadata, not the device credential. The Connector combines that metadata with its locally held credential, saves it with the existing bounded/atomic private-file helpers, then starts its worker.

Unconfirmed registration and a configured-but-offline device are different states. The website marks a never-connected registration as setup in progress and waits for a real Connector heartbeat before showing online. Completing Google approval alone does not establish macOS permissions or a working remote session. Manual key import is an advanced recovery path.

Design references: [native apps and an external browser](https://www.rfc-editor.org/rfc/rfc8252.html), [device authorization security considerations](https://www.rfc-editor.org/rfc/rfc8628.html#section-5), and [same-origin CSRF defenses](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). MacLink's enrollment is its own application registration flow using the existing web Google OAuth client; it is not Google's OAuth device grant.

## Media and input

Screen video, system sound and remote input use WebRTC exclusively. System audio is captured by ScreenCaptureKit; the microphone is not captured. Bounded audio buffers are flushed whenever authorization pauses or the attachment closes. Automatic mode tries direct/configured TURN candidates and can retry with browser-side TURN/TLS 443. If both fail, it ends with an actionable network error. The Connector currently uses STUN; both sides blocking outbound UDP can still prevent connectivity even with browser-side TURN.

Ultra can send captured 48 kHz stereo float32 PCM over the separate `maclink-system-audio` WebRTC data channel. Each `MLP1` packet has a 16-byte little-endian header and at most 960 interleaved frames. The unordered channel uses zero retransmissions to avoid accumulating stale sound; packet loss can therefore cause gaps. The browser starts with a 120 ms target buffer, adapts it by 20 ms after an underrun up to 200 ms, and caps queued audio at 250 ms. Brief gaps retain the remaining samples and refill the same gesture-authorized AudioContext without also playing Opus. A sender pause flushes stale queued samples before refilling. No packets for 1.5 seconds or no resumed playback for 2 seconds ends the recovery attempt and falls back to Opus with a specific status message. The Connector paces 960-sample blocks against monotonic deadlines so scheduler and encoding work do not accumulate into a slow producer; short catch-up is limited to one block per 10 ms, and stalls over 100 ms flush stale audio and re-anchor the clock. It needs about 3.1 Mbps before transport overhead, in addition to video. The browser enables PCM only after a sound-button gesture and a live ready exchange, and shows PCM only after playback starts. Unsupported/unready playback falls back to a per-sender 192 kbps Opus music encoder. The RTP fallback stays available, but only one playback path is audible at a time. Authorization, capture permission, quality, backpressure and attachment state gate PCM; pause/close flush both paths. No microphone is captured. PCM avoids an additional lossy codec after capture; it does not undo OS mixing/resampling or promise source-file bit identity.

The website has no frame upload/download, remote input queue or HTTPS media transport. Ordinary HTTPS remains necessary for login, metadata, authorization and SDP/ICE signaling. TURN relays encrypted WebRTC packets; it does not decrypt media or the data channel. Data channels still enforce native event validation, sequence checks, view-only scope and macOS permissions.

The last decoded frame is retained only in bounded browser memory during recovery. It is revealed/replaced based on actual decoded frames. Input releases on focus loss, transport loss, permission pause or session replacement. The browser's timer fallback for browsers without `requestVideoFrameCallback` is still required and is unrelated to a network relay.

## Audio demand and input latency

The viewer sends an exact `audio-state` request (`type`, boolean `enabled`, uint32 `revision`) over the existing audio data channel. The Connector acknowledges the same revision with `supported: true`; reordered requests cannot re-enable an older intent. Audio enable still requires the current authorized peer and fresh local permissions. Mute closes native system-audio capture, invalidates old capture callbacks, flushes buffers, and blocks audio frame production, stopping Opus encoding and RTP audio packets. Unmute starts a fresh capture. Opus-only playback does not prepare the unused float PCM FIFO. The regular sound button controls mute; PCM has its own explicit gesture button so unmuting does not unexpectedly add PCM traffic.

Host stop is shown as applied only after a matching acknowledgment. Older Connectors ignore the request safely and retain their existing audio path; the viewer states that only browser playback is muted until host support is confirmed. A website update alone cannot install these native changes. The downloadable app remains the previously approved build until a separate Connector package update is authorized.

Mouse moves retain only the newest unsent position at a 16 ms cadence with a 4 KiB soft queue limit. Keys, pointer buttons and release remain ordered barriers; a 64 KiB hard limit closes the congested control channel rather than retaining unbounded stale input. Resolution, FPS targets and encoder quality policies are unchanged.

Native privacy queries run on one worker: active sampling every 50 ms with results expiring after 100 ms, and idle sampling every 500 ms with a 600 ms expiry. Activation invalidates idle grants and waits for a fresh active result. Slow, failed or stale checks pause media/input without treating unknown state as a confirmed revocation; only a fresh denial ends the attachment. Capture and actual input injection retain live native permission checks, and session/owner/authorization gates remain enforced on each operation. Snapshots never extend a permission or server lease.

## Permission polling and recovery

The Connector starts status checks every four seconds, including time spent waiting for the prior response. A poll has a six-second timeout; mutations retain their normal timeout and are not automatically retried. Outages back off to at most ten seconds.

Without fresh authorization for 17 seconds, the Connector pauses screen/system-audio transmission and input. It can retain the existing peer for up to 30 seconds, then closes it. Local macOS permission revocation closes it immediately. Only a fresh active session with the same attachment and generation resumes the retained peer. Late closes, captures and SDP answers cannot mutate a replacement attachment.

Viewer metadata polling, device online thresholds and server session leases remain necessary. Data-channel pings never extend the authorization lease. Diagnostic reports allow only states/counters and omit SDP, ICE addresses, credentials, screen contents and keystrokes.

## Quality targets

| Profile | Maximum width | Target FPS | Target / maximum encoder rate |
| --- | --- | --- | --- |
| low | 1600 px | 15 | 2 / 4 Mbps |
| balanced | 1600 px | 24 | 4 / 8 Mbps |
| high | 2560 px | 30 | 8 / 16 Mbps |
| ultra | 2560 px | 60 | 16 / 40 Mbps |

Preserve source aspect ratio without upscaling. Odd dimensions can round down for codec alignment. These are settings, not measured throughput or guarantees. Negotiated codecs, congestion control, host performance and network conditions affect actual results. A current encoder acknowledgment marks a profile applied.

## Storage and migration

D1 stores account/session metadata, device keys as hashes, owner/login-bound sessions, signaling and encrypted TURN configuration. The active app requires `DB`; it no longer needs an R2 binding. Migration `0006_remove_https_relay.sql` removes the retired input table and session transport discriminator. Keep historical migrations unchanged so existing databases can advance in order.

Before activating the new production release, end old sessions and remove any legacy `frames/` objects in the previous R2 bucket through the hosting administrator's storage controls. Removing an R2 binding or a SQL table does not itself delete old R2 objects. The old public deployment must remain on its existing bindings until it is replaced. Preserve device registrations, authentication data and TURN settings. The account-access migration drops invitation-related schema, and legacy remote sessions without an owner/login binding are denied and ended by runtime authorization checks.

Policies in this source describe the new WebRTC-only build. Do not publish those policies over a production build that still accepts screen/input uploads. Provider-specific processing countries and backup/log retention require final confirmation from the hosting agreement.

## Build and verification

Use Node.js 22.13+ and pnpm 11.25.0 for the website, with deployment-specific `.openai/hosting.json` containing the existing project ID and `d1: DB`. Google configuration is server-only.

```bash
cd MackLink_Web
pnpm install --frozen-lockfile
node --experimental-strip-types --experimental-sqlite --test tests/*.test.mjs
pnpm exec tsc --noEmit
pnpm build
```

Build the Connector on macOS with a macOS 13-compatible Python 3.11–3.14. The app includes Python. The default build performs a non-connecting executable self-test; use `--no-self-test` when no invocation of the built executable is allowed. Static Mach-O and signature checks still run.

```bash
python3 scripts/sync-connector.py --check
bash scripts/build-macos-app.sh --no-self-test
.build/maclink/venv/bin/python -m unittest discover -s MackLink_Web/tests -p 'test_*.py'
hdiutil verify dist/MacLink-Connector-arm64.dmg
```

Stop an installed Connector before replacing its bundle. Back up the previous app, retain the private key/configuration, verify version and executable bytes, and do not launch it when installation-only was requested. A same-version ad-hoc rebuild can require renewed macOS permission registration on its next launch. Installation alone does not prove a remote session works.

# MacLink 연결 보안 검토

검토일: 2026-10-17. 범위: 웹 로그인·기기 등록·초대·ICE·세션·입력/화면 중계, 커넥터의 승인·권한 확인·연결 키 가져오기 및 설치 경로. 소스와 자동 테스트를 검토했으며, 외부 침투 시험이나 모든 의존성의 취약점 전수 조사를 수행한 것은 아닙니다.

## 이번에 적용한 변경

- 원격 접속 폼의 접속자 이름을 **호스트 이메일 주소**로 대체했습니다. 초대 링크와 기기를 소유한 Google 계정의 이메일이 모두 맞아야 새 연결을 만들 수 있습니다.
- 웹 로그인은 Google OpenID Connect의 `state`·`nonce`·PKCE 검증과 서버가 발급한 불투명 `HttpOnly` 세션 쿠키를 사용합니다. `GET /auth/google?return_to=%2F`에서 시작하며 로그아웃은 `Origin`을 검사하는 같은 출처의 `POST /auth/signout`으로 처리합니다.
- 소유자는 Google `sub`로 식별합니다. 클라이언트가 보낸 소유자 헤더나 이메일 문자열만으로 계정을 연결하지 않으며, 이메일이 이전 계정과 같아도 기기 소유권을 자동 이전하지 않습니다.
- 이메일은 앞뒤 공백 제거·소문자 변환 후 소유 계정 ID와 묶어 SHA-256 해시로 저장합니다. `+별칭`이나 점을 임의로 지우지 않습니다. 이메일 해시는 암호화나 고엔트로피 비밀번호를 대체하지 않습니다.
- `/api/ice`와 `/api/join` 모두 같은 검증을 수행합니다. 화면 연결 전에 발급하는 TURN 자격 증명도 검증을 통과해야 받을 수 있습니다. 이름만 보내는 구버전 API 호출도 새 연결을 만들 수 없습니다.
- 초대별 이메일 확인 실패 예산은 5분에 10회입니다. 두 API가 예산을 공유하고, DB에서 원자적으로 검사 자리를 예약해 동시 요청도 제한합니다. 성공한 검사는 자리를 반환합니다. 한도에 도달하면 올바른 이메일도 잠시 차단되므로 호스트가 새 초대를 발급할 수 있습니다. 실제 호스트 이메일이나 일부 글자는 오류 응답에 노출하지 않습니다.
- 최초 보안 개선에서는 새 초대의 기본값을 일회용으로 바꿨으나, 이후 사용자 요청으로 **상시 접속 링크를 기존 기본값으로 복원했습니다.** 일회용 초대(1시간 안에 1회)도 선택할 수 있습니다. 호스트 이메일 검증은 두 종류에 모두 유지합니다. 일회용 요청은 서버에서 승인 대기 상태가 되며, 커넥터에서 무인 승인을 따로 켜두었다면 자동 승인될 수 있습니다.
- 응답에 `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`를 적용했습니다. 기존 CSP·다운로드·스트리밍 헤더는 보존합니다.
- 접속자 이름을 실제 인증된 사람처럼 표시하지 않고 중립적인 ‘원격 접속자’로 표시합니다. 현재 접속자의 계정을 인증하는 기능은 추가하지 않았습니다.

## 사용 시 달라지는 점

Google로 로그인한 뒤 기기를 등록합니다. 이전 계정의 기기는 이메일이 같아도 자동으로 현재 계정에 연결되지 않습니다. 기존 연결 키를 가진 소유자는 **내 기기 → 기존 연결 키로 기기 가져오기**에서 JSON을 선택하고 현재 Google 계정으로 가져오기를 명시적으로 확인할 수 있습니다. 이미 다른 Google 계정에 귀속된 기기는 가져올 수 없습니다. 파일은 16 KB 이하로 제한하며 기기 ID와 연결 토큰만 같은 출처의 서버로 보냅니다. 파일의 사이트 주소로 요청하지 않으며 키를 브라우저 상태·저장소·로그에 보관하지 않습니다. 이전 계정의 TURN 설정은 자동 이전하지 않으므로 다시 구성해야 합니다.

호스트 이메일은 Google 로그인 계정과 초대 창에서 확인하며 초대 URL에는 넣지 않습니다. 이메일은 소유권 증명이나 계정 연결 수단이 아닙니다.

기기 가져오기를 확인하면 해당 기기의 기존 초대 링크와 접속 세션은 종료되므로 새 초대를 발급해야 합니다. 새 연결에는 호스트 이메일 검증이 적용되며 기존 세션의 복구는 세션 키로 인증합니다. 전체 권한 회수 버튼도 기존 초대와 세션을 함께 폐기합니다.

**호스트 이메일은 공개될 수 있는 식별 정보입니다. 이 변경은 접속할 호스트의 확인을 보강하지만, 접속자의 신원 확인·이메일 소유 인증·다중 요소 인증은 아닙니다.**

## 확인한 보호 경계

소유자별 기기 관리, 기기·세션 비밀 키의 해시 비교, 승인 전 공유/입력 차단, 보기 전용 입력 차단, 세대가 지난 응답·입력 폐기, 권한 회수 후 재접속 차단을 API 테스트로 확인했습니다. 커넥터는 현재 세션·세대·macOS 권한·최근 서버 권한 확인을 검사합니다. 기존 4초 폴링과 17초 권한 유효 기간은 변경하지 않았습니다.

새 테스트는 정상/오류 이메일, 이름만 보낸 직접 API 요청, 다른 소유자 이메일, 구 기기의 최초 이메일 등록, 개인정보 응답, 시도 제한·동시 요청·시간 경과 후 복구 및 보안 헤더의 스트리밍/다운로드 호환성을 검사합니다. Google OIDC와 기기 가져오기 경로는 인증·세션·소유권 서버 테스트로 별도 확인해야 합니다. 운영 환경의 실제 Google 로그인과 원격 화면·키보드 전체 동작은 소스 단위 테스트만으로 입증할 수 없으며, Google OAuth 자격 증명 구성 전에는 실제 로그인을 검증하지 않았습니다.

## 1.3.2 배포 준비 변경

- 화면·입력 HTTPS 보조 중계, JPEG 업로드·조회, 입력 대기열, 프레임 상태 응답과 구버전 중계 호환 코드를 제거했습니다.
- WebRTC와 암호화된 TURN만 화면·입력을 전달하며, HTTPS 보안 통신은 로그인·권한 확인·시그널링에 유지합니다.
- 마이그레이션 `0006_remove_https_relay`가 이전 입력 테이블과 전송 구분 열을 제거합니다. 운영 배포 시 예전 R2의 `frames/` 객체는 별도로 정리해야 합니다. 새 코드를 설치하는 것만으로 이전 서버 데이터가 삭제되지는 않습니다.
- 기기 키 파일·초대 링크·메뉴바 웹사이트 버튼은 `https://www.maclink.cloud`를 사용합니다.
- 실제 Google 로그인과 새 원격 세션 검증은 OAuth 설정 후 새 버전 활성화 시 별도로 수행해야 합니다.
